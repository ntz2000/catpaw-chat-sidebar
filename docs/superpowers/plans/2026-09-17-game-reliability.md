# Workspace 游戏可靠性迭代计划

> 本计划用于把 8 个小游戏从“可以打开”提升到可反复游玩的稳定状态。项目当前不是 Git 工作区，因此以编译、单元测试和最终 VSIX 打包作为每轮验证依据。

## 目标

- 统一使用 W/A/S/D；空格、Enter 只用于确认、跳跃或硬降等明确动作。
- 把关键规则移入无 DOM、可单测的 `media/game-core.js`。
- 修复游戏结束、碰撞、得分、重开和切换页面后的生命周期问题。
- 每完成一组规则即运行回归测试，再接回游戏界面。

## 实施顺序

1. 为 Snake、Flappy、Mines、Sudoku、Bubble 添加纯规则与回归测试；补足 2048、Breakout、Tetris 的边界测试。
2. 将 8 个 UI 实现改为调用这些规则，避免 UI 代码自行维护另一套规则。
3. 统一暂停、重开、销毁行为，确保切换模块不会遗留定时器、动画帧或键盘监听。
4. 做手工逻辑检查、编译、测试、VSIX 打包，并修复发现的问题。

## 核心规则

- Snake 撞墙或撞自身结束，不穿墙；吃到食物后增长。
- Flappy 撞管道、地面或顶部结束；每根管道只能计一分。
- 2048 每次有效移动后才生成新数字；2048 后可选择继续；无可移动格才结束。
- Breakout 撞砖后立即移除该砖；球越过底部且没碰到挡板时扣生命/结束。
- Tetris 使用 W 旋转、A/D 横移、S 软降、Space 硬降；清行、升级和下一块状态一致。
- Mines 首次打开永远安全；旗帜、连锁展开、胜负和计时一致。
- Sudoku 仅标记同一行、列或宫内的重复数字，不把“与答案不同”误判为冲突。
- Bubble 每个气泡只计一次，重置/重生成后状态干净。

## 验证

- `npm test`：覆盖每个游戏至少一项关键成功路径和一项失败/边界路径。
- `npm run compile`：验证扩展宿主 TypeScript。
- `npm run package`：生成可安装 VSIX。
